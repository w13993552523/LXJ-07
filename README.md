# 老乡鸡产品溯源系统 · 需求评审原型

版本日期：2026-10-23。纯静态 HTML、CSS、JavaScript 项目，无需 npm 安装或构建。

## 本次包含的最新修改

- 原料、半成品、菜品的关联溯源卡改为三列抽屉列表（序号、更新时间、查看）；详情按 PLM 的 35 个字段展示，供应商及感官、理化、微生物指标以结构化表格查看，保留返回抽屉操作。
- 菜品显示配置新增“按原料批量关闭展示”：按编码/名称搜索原料，选择关联菜品，确认影响范围后批量关闭该原料展示。支持全选、已关闭跳过、取消和本机保存；与单菜品配置及消费者报告预览联动。
- 正向、逆向、菜品溯源报告的央厨加工字段“流水线”改为“班组”，支持多个班组展示。生产订单管理保持原有字段。
- 菜品详情新增“制作工艺”Tab，包括工艺版本、加工方式、设备、用时、质量控制点、出餐要求和分步加工说明。均为演示内容。

## 保留的此前功能

- 原料正向、逆向报告摘要新增供应商资质链接，弹框内支持筛选、分页及导出，并保留来源环节、原料、收货单关联。
- 正向、逆向、菜品报告移除牧场出库与农场养殖；左侧移除养殖管理菜单。
- 三类报告详情表格和关联弹框支持 CSV 导出，导出当前筛选结果的全部分页记录。
- 原料详情新增原料验收标准 Tab；生产订单增加多值车间、流水线；司机详情增加健康证信息。
- 消费者报告支持条件圈定、本页多选、跨页多选、全部筛选结果选择及批量关闭；提供影响范围、原因填写和结果清单。

## 上传 GitHub

1. 解压 ZIP，新建一个 GitHub 仓库，例如 `lxj-trace-demo`。
2. 上传解压后的全部内容到仓库根目录，确保 `index.html`、`assets`、`README.md` 在同一层级。不要只上传 ZIP，也不要多包一层发布包目录。
3. 提交到 `main` 分支（或实际用于发布的分支）。免费账号可使用公开仓库部署 GitHub Pages。
4. 在仓库 **Settings → Pages → Build and deployment**，将 **Source** 设置为 **Deploy from a branch**。
5. 选择 **main** 和 **/(root)**，点击 **Save**。
6. 等待部署成功后，在 Pages 页面打开生成的地址。一般为 `https://你的用户名.github.io/仓库名/`。

资源均使用相对路径，适用于 GitHub 仓库子目录网址。页面通过 hash 切换路由，刷新详情页无需额外重写规则。

`.nojekyll` 用于跳过 Jekyll 处理。Mac 按 Command + Shift + . 可以显示隐藏文件。

若发布后 404，先确认 `index.html` 位于所选分支根目录，再查看仓库 Actions 内的 Pages 部署结果。

官方说明：https://docs.github.com/en/pages/getting-started-with-github-pages/configuring-a-publishing-source-for-your-github-pages-site

## 本地打开

直接用浏览器打开 `index.html`；也可以在本目录运行：

```sh
python3 -m http.server 8000
```

然后访问 `http://localhost:8000`。

## 演示说明

- 数据与凭证为原型示例，未接入真实业务或消费者服务。
- 配置、关闭状态等保存在当前浏览器本地存储，不会跨设备或跨域名同步。
- 重新生成消费者报告不会自动解除已关闭状态。
- 页面右上角“恢复演示数据”可重置当前浏览器的原型数据；有需要保留的配置时不要使用。
- 保留原项目的在线图标样式引用，访问该样式地址需要网络连接。
- 包内不含浏览器个人数据、Git 历史、其他项目或托管凭证。

## 2026-10-30 报告概要与溯源环节定义

- 所有溯源报告详情的报告概要隐藏“供应商模板编码”；正向报告概要另隐藏“关联菜品”，列表和业务数据保持原口径。
- 菜品报告和消费者报告概要统一提供“构成原料说明”链接，弹框展示原料编码、名称、批次号、实收数量、原料供应商及关联原料溯源报告。按关联逆向报告逐条展开，不按原料名称合并不同批次或收货记录。支持查询、分页、导出和新标签页查看关联原料报告。
- 溯源模板总览每行增加“溯源环节定义”，并显示正向开始、逆向开始和非必要环节。默认正向为仓储入库，逆向为门店收货；非必要环节支持多选。
- 配置范围来自当前菜品关联的已启用模板。同名环节合并展示，保留全部来源。已选开始环节不能勾为非必要，勾选非必要的环节不能选为任一方向起点；保存时再次校验。可先更换起点，再将原起点设为非必要。
- 保存按菜品生效并写入浏览器本地存储；取消不修改，重新进入和刷新后可回显。关联模板为空时禁止保存，旧定义不在当前范围时提示调整。

## 2026-11-02 按原料链路定义溯源环节

- “溯源环节定义”新增链路选择器。先按各原料及其供应商分支组成链路，再根据标准化环节名称与排列顺序去重；不同模板编码或版本的相同业务链路合并，保留来源信息。相同环节集合但排列顺序不同的链路分别配置。
- 弹框展示当前链路的关联原料、供应商、环节顺序及来源。只列出所选链路的环节，避免将其他原料的环节混入当前链路。没有已启用原料模板时，不把菜品自身环节当作完整原料链路。
- 每条链路分别保存正向开始、逆向开始和非必要环节。切换链路保留本次未保存修改；“保存修改”校验并保存本次修改的全部链路，取消则放弃本次修改。起点与非必要环节继续互斥。
- 默认起点仍为仓储入库和门店收货；若所选链路不含对应环节则显示“待定义”，需要从该链路实际环节中选择。旧菜品级配置首次按各链路可用环节迁移；新增链路不沿用其他链路的设置。
- 配置使用菜品及稳定链路标识关联，原料顺序调整不会导致已保存定义串链。总览列表中不同链路定义不同时显示“按链路配置”，点击进入查看和修改；相同定义直接显示对应值。

本次调整替代前述菜品／链路级“溯源环节定义”入口。
